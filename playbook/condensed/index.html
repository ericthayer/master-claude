01Brief Claude like a teammate

Learn how Claude works and how to brief it so the first answer lands close.

About 10 minutes · 2 parts

What Claude is

Claude is an AI model from Anthropic that you talk to in everyday language, at claude.ai or in the desktop and mobile apps. Think of it as a fast, well-read collaborator who has never seen your project. It knows interface patterns, HTML, and accessibility. It knows nothing about your users or your taste until you tell it.

Tip

Keep one topic per chat. Claude remembers the whole conversation, which helps when you iterate on one prototype and gets in the way when you switch topics.

Write prompts like design briefs

A good prompt sets context, states the task, names the constraints, and describes the deliverable. Here's one, annotated like a spec.

  • Attach screenshots. Claude reads images, so show it the Figma frame or page you mean.
  • Ask it to ask you. End big requests with "Before you start, ask me any questions you need answered."
  • Change one thing at a time. Small follow-ups are easier to judge than a full rewrite.
Good to know

The Pro plan covers everything in this guide. Max mainly adds room to iterate for longer without hitting usage limits. Check claude.com/pricing for current plans.

02Put your work on GitHub

GitHub stores your portfolio files, keeps every version, and publishes your site for free. Everything here happens in your browser.

About 25 minutes, hands-on · 3 parts

Four Git words

Repository (repo)

A project folder that remembers every change made to it.

In Figma: a file with version history built in.

Commit

A saved snapshot of your changes, with a short note about what changed.

In Figma: naming a version.

Push

Sending your commits from your computer up to GitHub.

In Figma: your edits syncing to the cloud.

main

Your repository's default version. Your live site publishes from it.

In Figma: the main file, not a branch.

Create your account and repository

0 of 4 done
  1. Sign up at github.com/signup.

    Your username becomes your site address, username.github.io, so pick something close to your name.

  2. Turn on two-factor authentication.

    Settings → Password and authentication. GitHub will ask you to do this anyway.

  3. Create a repository named username.github.io.

    Click + → New repository. Keep it Public, turn on Add a README file, and click Create repository.

  4. Add your homepage.

    Click Add file → Create new file, name it index.html, paste the starter below, then click Commit changes.

Publish with GitHub Pages

0 of 3 done
  1. Open Settings → Pages.

    Settings is a tab at the top of your repository.

  2. Publish from main.

    Set Source to Deploy from a branch, choose main and / (root), then click Save.

  3. Wait a minute, then visit your site.

    Refresh the Pages screen to see your address. From now on, every commit to main updates the site.

Seeing a 404?

Check that the file is named exactly index.html and sits at the top level of the repository, not in a folder. Then wait a few minutes and refresh.

Stuck? Ask Claude

  • I'm setting up GitHub Pages for the first time and I'm stuck on this step: [describe it, or attach a screenshot]. Tell me exactly what to click next.

03Connect your tools

Two connections cover most of your work: a Project that remembers who you are, and Claude Code to edit your real site. Three design skills then add reviews and planning.

About 20 minutes, hands-on · 3 parts

Set up a Project

A Project keeps instructions and files attached to every chat inside it, so you only explain yourself once.

0 of 3 done
  1. Create a Project.

    At claude.ai, open Projects and create one called "Portfolio 2026".

  2. Paste in the instructions below.

    Fill in the pink parts first. Claude reads them at the start of every chat in the Project.

  3. Add your repository.

    In the Project's knowledge section, click + → GitHub. If asked, allow only your portfolio repository.

Start Claude Code

Claude Code works inside a folder on your computer. It edits files and saves your work to GitHub, and it asks before it changes anything.

0 of 3 done
  1. Copy your repository to your computer.

    Install GitHub Desktop, sign in, then choose File → Clone repository and pick a folder such as Documents/portfolio.

  2. Open it in the Claude desktop app.

    Go to the Code tab and choose that folder. Prefer VS Code? Install the Claude Code extension instead.

  3. Send your first prompt.

    The one below only reads, so nothing changes yet.

Heads up

Commit your work before asking for big changes, so you can always go back. Read each permission request before you approve it.

Add three design skills

Skills teach Claude Code a repeatable way of working. These three are free plugins: Impeccable reviews and polishes your design, Agent Skills writes a spec before bigger changes, and UI UX Pro Max critiques and refines layout, color, and type.

These need the terminal version of Claude Code. In VS Code, type /plugins to add and install them from a dialog instead. Restart Claude Code when you're done. UI UX Pro Max also needs Python 3.

04Three portfolio prompts

From a plan to a live site. Use them in order, since each builds on the last.

Use as needed · 3 prompts

Tip

Paste your résumé, rough notes, or a screenshot below any prompt. Claude can only use what it can see. Remove anything confidential first.

1. Portfolio strategy

Use it when you want to decide what your portfolio should say before designing anything.

  • Which 3 projects should lead, and in what order? Explain the story they tell together.

2. Case study writing

Use it when you have a project and some notes, and need a story someone can skim.

  • Cut this to a version someone can skim in 90 seconds, with headings and a TL;DR at the top.

3. Portfolio website build

Use it when your strategy and one case study are ready, and you want the full site.

  • Check the whole site for accessibility issues and fix them. List what you changed.

Changing the site later? Agree on a spec first with Agent Skills, then run /plan and /build one small step at a time.

  • /spec I want to refactor [what, e.g. the navigation] on my portfolio. Keep my content, colors, and fonts. Ask me questions until the spec is clear, and don't write any code yet.
Before you publish

Check every fact Claude writes about you, especially numbers, dates, and job titles. Claude only knows what you've told it.

05Make it a habit

One routine behind every task, and seven prompts to keep close.

About 5 minutes, then ongoing · 2 parts

The five-step loop behind every task

When a result disappoints, one of these steps usually got skipped.

  1. Brief

    Context, task, constraints, and format. Attach a screenshot.

  2. Generate

    Let Claude draft. Ask for options when you're exploring.

  3. Review

    Test it in a browser, at phone width, and with a keyboard.

  4. Refine

    Change one or two things at a time. Say what to keep.

  5. Ship

    Save it to your repo with a clear commit message.

Then repeat for the next change

Starter Kit

Seven prompts worth keeping close. The last two use the design skills from Frame 03. Copy them into your notes or a prompts.md file in your repository.

Glossary

Plain-English glossary

The words you'll meet first. Git terms are in Frame 02.

Prompt
The message you send Claude. A good prompt reads like a design brief.
Context
Everything Claude can see while it answers: the conversation, attached files, and Project instructions.
Artifact
Something Claude makes that opens in its own panel, like a web page or diagram. You can share it with a link.
HTML and CSS
HTML is a page's structure. CSS is its styling: color, type, spacing, and layout.
Responsive
A layout that adapts to any screen size, from phone to desktop.
Accessibility and WCAG
Designing so people with disabilities can use your work. WCAG 2.2 AA is the standard most teams aim for.
GitHub Pages
GitHub's free hosting for websites, published straight from a repository.
Claude Code
Claude working inside a folder on your computer, editing real files after you approve.
Skill
A saved set of instructions that teaches Claude a way of working, like a design review. You add skills to Claude Code as plugins.
Spec
A short written plan: what you're building, why, and how you'll know it's done.
